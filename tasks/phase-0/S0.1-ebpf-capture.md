# Spike S0.1 — eBPF capture of a live agent, filtered by cgroup

**Phase:** 0 (de-risk) · **Kill-risk rank:** 1 (highest) · **Owner:** —
**Kills:** *Does kernel-truth, cross-agent capture actually work on a real agent?* If eBPF can't cleanly capture exec+connect for a real coding agent filtered by cgroup, the entire thesis is invalid and the architecture changes before Phase 1.

## Goal
Prove that a small eBPF program set, loaded from Go via cilium/ebpf with CO-RE, can capture `exec` and outbound `connect` events for a **live Claude Code session**, filtered to that session's cgroup, decoded in userspace, with zero interference to the agent.

## Setup
- Linux box, kernel ≥ 5.15, cgroup v2, BTF present (`/sys/kernel/btf/vmlinux`).
- Go ≥ 1.24, cilium/ebpf + bpf2go, clang for the spike build.
- A working Claude Code CLI to drive real activity.

## Steps
1. Write three CO-RE programs:
   - `sched_process_exec` tracepoint → emit {pid, ppid, cgid, comm, argv-truncated} to a ringbuf.
   - `cgroup/connect4` (BPF_CGROUP_SOCK_ADDR) → emit {pid, cgid, daddr, dport}.
   - **(v1.1 — now load-bearing, de-risk here)** fentry on a VFS/security-layer function for file opens with an **in-BPF resolved-path walk** (bounded dentry+mount loop, Tracee/Tetragon pattern) → emit {pid, cgid, resolved path, flags}. Must resolve symlinks and relative/`dirfd` opens correctly on a stock 5.15 kernel — this is what D7's `path_source=resolved` tier stands on.
2. `bpf2go` the objects; load from a Go harness; attach.
3. Create a cgroup v2 leaf; write the harness's own PID (and thus its children) into `cgroup.procs`; pin `cgid` into a filter map; make both programs drop events whose `cgid` isn't in the map.
4. Launch `claude` as a child inside the leaf. Drive it: ask it to edit files and hit the network (install a package, fetch a URL).
5. Read the ringbuf in Go; print decoded events.

## Success criteria
- [ ] Every `exec` in the Claude Code process tree appears, attributed to the session cgid.
- [ ] Outbound connects (package registry, API) appear with correct dest.
- [ ] File opens report **kernel-resolved paths**: a write via symlink and a write via relative path + `dirfd` both resolve to the real absolute path (v1.1).
- [ ] **Zero** events from processes outside the cgroup leak into the ringbuf (run a noisy unrelated process to confirm in-kernel filtering).
- [ ] Agent shows no behavioral change and no measurable slowdown (`P2`/G7 smoke).
- [ ] Kill the harness mid-session → Claude Code keeps running unaffected.

## Deliverable
`spikes/S0.1-report.md`: what worked, kernel/BTF quirks hit, per-event overhead measured, and a go/no-go with any architecture amendments. Seeds the Phase-1 hook implementation.

## Estimate
3–4 focused days (the dentry walk is the new hard part; budget a day for it).
