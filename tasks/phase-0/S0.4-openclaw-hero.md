# Spike S0.4 — OpenClaw hero: adopt, attribute the tree, label causality

**Phase:** 0 · **Kill-risk rank:** 4 · **Owner:** —
**Kills:** *Is the hero experience achievable?* `rana adopt openclaw` is the entire go-to-market. If we can't slot a real gateway into a session slice, capture its full fan-out (gateway → sub-agent → exec → egress) attributed as one session, and label causality by runId via a small plugin — then the headline doesn't exist.

## Setup
- A real OpenClaw install: gateway on `127.0.0.1:18789`, config under `~/.openclaw/`, launchd/systemd-supervised.
- The S0.1 capture set (exec + connect + a couple of fs ops).
- The `plugins/openclaw/rana-plugin.js` marker bridge from this pack.
- A messaging channel wired up (WebChat is simplest) to drive real agent runs.

## Steps
1. **Adopt (Linux):** write a systemd drop-in placing the gateway unit under `rana.slice/rana-openclaw.scope`; restart with confirmation. Verify the gateway PID and all descendants land in the leaf.
2. Install the marker plugin; set `RANA_MARKER_SOCKET` + `RANA_MARKER_TOKEN` on the gateway unit; stand up a throwaway Unix-socket listener that prints received markers.
3. Drive a channel message that makes the agent do something with real effects (run a shell command that touches a file and hits the network).
4. Confirm the captured events show the **whole tree** attributed to one session, and that `run.start`/`run.end` markers arrive carrying `{runId, agentId, channel, status}` — and **nothing else** (assert no message text ever crosses the socket).
5. Reconstruct, by hand from the captured stream + markers, the sentence: "message on <channel> (runId X) → these execs → this egress → this file changed."
6. **Cross-agent check:** run a Claude Code session (S0.1) at the same time; confirm two distinct sessions on one capture stream.

## Success criteria
- [ ] Gateway + all children captured as a single attributed session (cgroup inheritance holds through OpenClaw's fan-out).
- [ ] Markers arrive with identifiers only; a grep of the socket transcript for message content finds nothing (P7 holds end-to-end).
- [ ] The "conversation → consequences" narrative is reconstructable from data alone.
- [ ] Two agents run simultaneously resolve to two sessions, not one blob (cross-agent proven).
- [ ] macOS note (v1.1): run the gateway **inside the S0.2 guest** (Linux build on the data volume, `~/.openclaw` projected, :18789 port-forwarded) — there is no native-macOS recording path, degraded or otherwise; confirm adopt's decline message states this plainly.
